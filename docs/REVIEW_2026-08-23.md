# Hard review — Mobiscout, second pass (2026-08-23)

A five-dimension adversarial review run after the `docs/AUDIT_2026-08.md` backlog was
fully remediated, so it deliberately avoids that ground and digs elsewhere: engine hot
path, JetBrains plugin, test-suite honesty, security/robustness, and product/GTM. Every
finding below was read first-hand and the headline ones re-verified against the code by a
second pass (marked ✅).

## The spine

The product is sold on one promise — **"generated tests pass in CI"** — and that promise
is both **unverified** and, in specific ways, **broken**. Three layers reinforce each
other: the engine emits semantically wrong tests → the suite can't catch it because no
test *executes* an emitted kit → the product ships no proof the promise works on a real
app. It is one hole running the length of the stack, not a scatter of nits.

## What is genuinely good

The crawl loop is defensive about flaky devices and is tested against a fake UI graph
(`tests/test_pipeline.py`); the codegen behavioural assertions encode real domain
knowledge (settle-after-actions, anti-flake bans, iOS/Android gating); the subprocess
surface is clean (argv lists, no `shell=True` — no command injection); the 0.10.0
activation work (autodetect, auto-boot, self-installing engine) is real and the v0.10.0
release is complete across all four platforms.

## P0 — breaks the core promise / dangerous

### 1. No test ever executes a generated kit; CI "Integration Tests" is `mobiscout --help` ✅
Kits are gated by `py_compile` only (`tests/codegen/test_emitters.py:150`); the Java/Kotlin
gates pass most real breakage. The CI `integration-test` job installs adb (never invoked),
starts a backend, `sleep 5`, then runs `mobiscout info` + `mobiscout --help` — the backend
gets zero requests. The only `pytest.main` calls are `[__file__]` inside test modules.
**Fix:** a loopback fake Appium W3C server (create-session/find/click/send-keys), then run
an emitted `python_pytest` kit as a subprocess to green in CI. This also anchors the
goldens externally and catches finding 2 before users do.

### 2. Codegen replays transitions under the wrong preconditions → red tests on well-behaved apps ✅
- `SCROLL_TO` is **never emitted** by the crawler (grep empty) → below-the-fold elements
  get a tap with no scroll → `NoSuchElementException`.
- The auth prefix is threaded only into `_screen_cases` (`to_codegen.py:510`) → navigation,
  multi-step and negative cases behind a login gate run without passing it.
- Negative-probe transitions are written to the graph unmarked → journeys fill the form
  with *valid* data and then assert the *error* screen.
**Fix:** a typed `Transition` dataclass (kind: tap / submit-probe / gate / scroll-revealed /
deeplink) — one refactor fixes all three (engine finding 8).

### 3. Dashboard: unauthenticated + binds 0.0.0.0 + path-traversal arbitrary file write ✅
`approve_selector` takes `file_path` from the DB: an absolute path is used as-is and `../`
is not blocked, and the write is not confined to `repo_path` (`server.py:108`);
`run(host="0.0.0.0")` is the default; no token/CSRF on mutating routes. (The path-traversal
was introduced by AUDIT §3's approve fix — a regression to own.)
**Fix:** bind `127.0.0.1`; `resolve()` + `is_relative_to(repo_path)`; reject absolute paths;
per-session token on mutating routes; vendor Alpine.js locally instead of the CDN.

### 4. Plugin JSON-RPC client: two readers on one stream — responses stolen, calls hang ✅
`startListening` starts (JsonRpcClient/MTRDaemonService) before `call("health/check")` on
the same `BufferedReader`; the listener can consume the health response → "Starting…"
forever, or a `logs/message` notification is parsed as a `kit/generate` result → `screens=0`.
No id-correlation, no write lock, no timeout.
**Fix:** single reader thread + `ConcurrentHashMap<id, CompletableFuture>` dispatch by id;
synchronized writes; per-call timeout.

## P1 — robustness & trust

### 5. Plugin: EDT-blocking start (incl. ~85 MB download) & synchronous RPC; no disposal; orphaned daemon; double-start window ✅
`start()` is called on the EDT in `actionPerformed` and in the dialog constructor
(`device/list`); it is not `@Synchronized` and `isRunning` flips only after the health
check; there is no `Disposable`/shutdown hook, so the engine process is orphaned on every
IDE exit; the daemon log is written to the IDE's CWD.

### 6. No proof the promise works; the showcase is synthetic and labelled "real" ✅
`examples/generate.py` is "device-free … builds a realistic CrawlResult", yet the READMEs
call it "a real, generated example". The R0 dogfood gate is unchecked. The README
contradicts itself ("engine mature / 8 targets" vs "Coming Soon (Phase 3+)" / "In
Development: connect all pieces"); `2023.2+` in the plugin README vs `sinceBuild=243`.
**Fix:** crawl a real installable app (AntennaPod), publish the kit with a green CI run + a
60-90s GIF, make it the centre of the listing; ruthless truth-pass over the docs.

### 7. "Zero setup" hides an Appium/Node prerequisite the listing denies ✅
iOS force-selects Appium (`GenerateKitDialog:238`) against `localhost:4723` the plugin never
starts; every kit is Appium code and the scaffold README tells the user to `npm i -g appium`
(Node unmentioned). plugin.xml says "No separate engine to install".
**Fix:** a pre-crawl doctor with an actionable error; honest Requirements; "how to run the
kit" in the success notification.

### 8. Daemon as an IDE backbone: no default wall-clock budget, no cancel, no size limit; iOS input fakes success ✅
`handle_swipe`/`handle_type` are unconditionally adb and return `{"status":"success"}`
without a returncode check — on iOS they lie; `type` escapes only spaces (breaks on
`& ; $`). `max_seconds` is off unless passed; the daemon is single-threaded and
`kit/generate` can't be cancelled from the IDE; no message-size cap (unbounded line read →
OOM).

## P2 — hygiene & positioning

### 9. Cloud grid — turn nagware into a real user-configured integration ✅ (revised per owner)
The PRO tab advertises a cloud grid (BrowserStack / Sauce Labs / LambdaTest) that ROADMAP
R2 had ruled out; the upgrade link 404s (private repo); `tierNote` writes "Upgrade to PRO"
in the free build.
**Decision (owner, 2026-08-23):** do **not** remove it — **implement** it as a real,
**user-configured** integration: the user connects their own provider account (BYO
credentials, so Mobiscout needs no backend) and runs generated kits on the grid from the
plugin. Until it's real, the tab must not advertise it as an existing feature and the link
must resolve. This supersedes ROADMAP R2's "cloud-grid out of scope" line.

### 10. Engine binary: cached copy executed unverified; same-origin sha256 overclaimed ✅
`ensureEngineBinary` trusts any `length()>0` cached file; the checksum runs only on the
download path. The `<asset>.sha256` is fetched from the same release as the binary — over
HTTPS that is corruption detection, not supply-chain defence (a compromised release
self-certifies), yet it reads as a security control.
**Fix:** re-verify the cached binary before each launch; download to `.part` + atomic
rename; pin the expected digest inside the plugin jar (out-of-band); owner-only perms.

### 11. Test-suite honesty
92 `assert ... is not None` (constructor tests that can only pass), goldens regenerated
from the code under test (circular anchor), live sockets in "unit" tests
(`DASTAnalyzer` hits :8080), unused `slow`/`integration` markers, `--cov-fail-under=80` vs
88% actual (8 points of silent rot), no pytest-timeout, wall-clock assertions.
**Fix:** delete constructor tests; assert content not shape; ratchet coverage to 87 + patch
threshold; pytest-timeout; apply markers.

### 12. Listing metadata
No vendor email in plugin.xml; plugin id `com.mobiletest.recorder` is the pre-rename
identity (permanent once published — decide now); verifier pinned only to `243.*`.

## Plan, by leverage (execution order)

1. **Loopback fake Appium + execute a kit in CI** (P0.1) — makes the promise testable,
   anchors goldens, and catches P0.2 before users. Highest leverage.
2. **Typed `Transition`** (P0.2) — fixes auth / scroll / negative-probe together.
3. **Dashboard security** (P0.3) — close before any publication.
4. **Rewrite the JSON-RPC client** (P0.4) + move `start()`/download to background with
   progress + `Disposable`.
5. **Dogfood a real app** + GIF + green CI kit (P1.6); truth-pass the docs; then the rest of
   P1/P2 in order, including the user-configured cloud-grid integration (P2.9).
