## Remaining / new findings (R)

### R1 — P1: one red test, and it's an environment-dependent one

`tests/test_native_analyzer.py::test_backend_is_python_without_the_wheel` asserts
"the wheel isn't installed here" as a fact about the environment. After the perf work
(#431–#433) `mobiscout_core` **is** installed in this venv, `backend_name()` correctly
returns `"rust"`, and the test is red locally while green in CI — the
"works in CI, fails on the dev box" inversion. It also reds the pipeline the day any CI
test job installs the wheel (likely, after #430 made bundling mandatory). This is the
exact test class P2.11's own cleanup criticized.

**Fix:** control the environment instead of assuming it — monkeypatch
`native._native_core` to return `None` (it is `lru_cache`d: call `cache_clear()` first),
and add the mirror test ("rust when the wheel is present") under `skipif`. The failure
itself is, incidentally, the first live proof the Rust wiring works.

### R2 — `DeviceList`'s docstring overclaims (S1 residue)

The new module's comment says it "replaces three near-identical loaders (**the dialog**,
the Screen panel, the Logs panel)" — but `GenerateKitDialog.loadDevices()` still
hand-rolls its own loader with `deviceNames`/`devicePlatforms` maps and a raw
`device/list` call. No bug (the combo item *is* the id; the name lives only in the
renderer), but the claim is false on day one. Migrate the dialog (an editable combo does
not preclude `DeviceItem`) or fix the comment.

### R3 — dialog validation: two gaps remain

`devicePlatforms` sits right in the class, yet `doValidate` does not catch
*platform = android, selected device = iOS* (only the install-build case was added).
And garbage in Max steps / Max depth silently becomes 40/8 (`toIntOrNull() ?: 40`) —
the user never learns their input was dropped.

### R4 — the mirror is still manual

Errors now surface (good), but there is no auto-refresh: the dead settings knob was
deleted (the right call) while the capability it promised was never built. With the new
ActionToolbar this is cheap — a "Live" toggle action driving a `javax.swing.Timer`
(1–2 s) while a session is active. Until then, plugin.xml's "mirror the screen" slightly
oversells a manual screenshot viewer.

### R5 — progress text can be hijacked by a concurrent log stream

`liveProgressListener` consumes **any** `logs/message`. If app-log streaming
(Logs ▸ Start App Logs) runs during a Generate, logcat lines flicker through the
progress bar. Cosmetic; a `source` tag in the notification params closes it.

### R6 — Inspector grew new JButtons on the day the panels lost theirs

#449 added `Capture UI Tree` / `Copy locator` / `Generate selector` as raw JButtons
while #452/#453 were converting the neighbouring panels to ActionToolbars. Cosmetic
inconsistency; same conversion applies.

### R7 — engine complexity backlog (unchanged, now tracked by the ratchet)

38 functions above C901-12 remain below the enforced ceiling of 22. The plan written
into ci.yml is right: after each hotspot refactor, lower the ratchet (22 → 21 → …).
