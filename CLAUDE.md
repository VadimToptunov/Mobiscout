# Engineering principles

How to work in this repo. Adapted from the Karpathy engineering principles
(multica-ai/andrej-karpathy-skills). Read before making changes.

## 1. Think before coding
- State assumptions explicitly; if uncertain, ask rather than guess.
- If there are multiple reasonable interpretations, present the tradeoffs — don't pick silently.
- If a simpler approach exists, say so; push back on unnecessary complexity.
- If something is unclear, stop and name what's confusing.

## 2. Simplicity first
- Build only what was asked. No speculative features, flags, or configurability "for later".
- No abstractions for single-use code.
- Skip error handling for genuinely impossible states.
- Senior-engineer test: would a senior call this overcomplicated? If so, simplify.

## 3. Surgical changes
- Change only what the task requires. Don't "improve" adjacent code, comments, or formatting.
- Match the surrounding style even if you'd personally do it differently.
- Remove only the dead code your change introduced — not pre-existing cruft (file that separately).
- Every changed line should trace back to the request.

## 4. Goal-driven, verified execution
- Define verifiable success criteria up front; turn vague asks into concrete tests.
- For multi-step work, outline the plan with verification steps.
- Loop until success is *demonstrated* (all gates below pass), not assumed.

## Project specifics

- **What this is:** an open-core (MIT) mobile test-generation engine — Python
  framework + Rust core + a Kotlin JetBrains plugin talking to a Python JSON-RPC
  daemon. It turns an app (via source, an OpenAPI spec, or a live crawl) into
  runnable UI and API tests. Paid limits live in the separate Mobiscout-PRO layer
  via the `framework.licensing` seam — the free engine defaults to UNLIMITED.
- **Gates that MUST pass before a PR** (CI enforces all):
  - `black --check` (pinned **26.5.1** — CI mismatch fails), line-length 120.
  - `flake8 --select=E9,F63,F7,F82`.
  - `mypy framework --ignore-missing-imports --no-error-summary` (**mypy 2.x** —
    catches things local 1.x misses; use a matching version).
  - `interrogate framework` (docstring coverage ≥ 90%, aggregate).
  - full `pytest`, and the JetBrains plugin `./gradlew verifyPlugin` → Compatible.
  - Windows CI is cp1252 by default: write/read files with `encoding="utf-8"`.
- **Golden codegen tests:** `tests/codegen/golden/`. Regenerate with
  `UPDATE_GOLDENS=1 pytest tests/codegen/test_emitters.py` ONLY on an intentional
  template change; a pure refactor must leave goldens byte-identical.
- **Commits/PRs:** never add "Generated by Claude Code" / "Co-Authored-By: Claude"
  anywhere. Branch off master → PR → wait for CI green → squash-merge → reset to
  master. Don't commit to master directly.
- **Stray artifacts:** running codegen/tests can drop `features/` and
  `test_scenarios.yaml` in the cwd — never commit them.
